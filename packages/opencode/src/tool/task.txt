启动一个新 agent 来自主处理复杂的多步骤任务。

使用 Task 工具时，你必须指定 subagent_type 参数来选择要使用的 agent 类型。

何时不要使用 Task 工具：
- 如果你想读取某个具体的文件路径，用 Read 或 Glob 工具代替 Task 工具，能更快找到匹配
- 如果你在搜索某个具体的类定义（如 "class Foo"），用 Grep 工具代替，能更快找到匹配
- 如果你在某个具体文件或 2-3 个文件中搜索代码，用 Read 工具代替 Task 工具，能更快找到匹配
- 如果没有可用的 agent 适合该任务，直接使用其他工具


使用说明：
1. 尽可能并发启动多个 agent 以最大化性能；为此，在单条消息中使用多次工具调用
2. 一旦把工作委派给 agent，就不要自己重复做那份工作。继续做不重叠的任务，或等待结果。对于后台任务，结果就绪时你会自动收到通知。
3. 当 agent 完成时，它会返回一条消息给你。agent 返回的结果对用户不可见。要展示结果给用户，你应该向用户发送一条文本消息，其中包含结果的简明摘要。输出中会包含一个 task_id，你可以稍后复用它来继续同一个 subagent 会话。
4. 每次 agent 调用都以全新上下文开始，除非你提供 task_id 来恢复同一个 subagent 会话（它会带着之前的消息和工具输出继续）。全新开始时，你的提示中应包含高度详细的任务描述，让 agent 自主执行，并且你要确切说明 agent 在发给你的最后一条也是唯一一条消息中应返回哪些信息。
5. agent 的输出通常应予以信任
6. 明确告诉 agent 你期望它写代码还是只做研究（搜索、读文件、网页抓取等），因为它不知道用户的意图。尽可能告诉它如何验证自己的工作（如相关的测试命令）。
7. 如果 agent 描述提到应主动使用它，那么你应该尽力在用户提出之前就使用它。自行判断。
