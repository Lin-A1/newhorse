# M3.5 规划：内置工具集

日期：2026-08-28
状态：设计规划（未实现）—— 锐评通过后实现。

---

## 0. 结论先行

**M3.5 做内置工具集**：给 agent 一双真正能干活的手。M3 的 DAG 已能调度 subagent，但节点里的 agent 没有任何真实工具（research/explore 只能靠模型裸答）——**成本平衡（便宜模型跑子任务）与"agent 干活"在没有工具时是空转**。工具先行，M4（Web UI / 跨进程）才有价值载体。

**范围**：六个核心工具，按"模型可正确使用"的工程标准实现——read / write / edit / list（glob）/ search（grep）/ bash。全部走现有 `Tool` 契约（M1 定的 `execute(input, ctx)`），注册进 `@newhorse/runtime` 的工具工厂，app 一行开启。

---

## 1. 工具清单（M3.5 最小集）

| 工具 | 输入 | 行为 | 安全边界 |
|---|---|---|---|
| `read` | `{ path, offset?, limit? }` | 读文件文本（默认 1000 行，行号前缀；`.git`/`node_modules`/二进制排除） | 经 `resolveInWorkspace` 沙箱校验，越界确定性拒绝 |
| `write` | `{ path, content }` | 写文件（全量覆盖；工作区内父目录自动 `mkdir`） | 经 `resolveInWorkspace`；属敏感工具（可落脚本，见 §2.2） |
| `edit` | `{ path, old, new, replaceAll? }` | 精确字符串替换（唯一匹配，除非 replaceAll）；old 不存在/空/等于 new 均拒绝 | 经 `resolveInWorkspace`；多处命中返回次数+各命中行号/上下文供模型消歧 |
| `list` | `{ pattern, path? }` | glob 列文件（如 `**/*.ts`；默认排除 `.git`/`node_modules`） | 经 `resolveInWorkspace`；上限条数（防巨型仓库刷屏） |
| `search` | `{ pattern, path?, include? }` | 内容正则搜索（类 grep），返回 file:line:match；默认 100 命中+截断标注 | 经 `resolveInWorkspace`；默认排除 `.git`/`node_modules`/二进制 |
| `bash` | `{ command, timeoutMs? }` | 执行 shell 命令，返回 stdout+stderr+exitCode | **不受 fs 沙箱约束**（见 §2.2）；M3.5 默认关闭（`config.tools.bash` 显式开启）；timeout clamp 60s；cwd 钉 workspace |

**明确不做**（M3.5）：web fetch、子 agent 工具（DAG 已覆盖）、持久记忆工具（M4）、read 图片/PDF（多模态 fast-follow，非本轮）；每个都留到后续按需加。

> edit 语义要点（锐评修正）：`old` 为空/`old === new` 必须拒绝（否则模型原地循环）；`new` 为空是合法删除（与旧空不对称）；CRLF 需归一化比较、写回保留文件原 EOL（否则 Windows 仓库 edit 成功率为零）；拒绝分支返回结构化信息（命中数+行号/上下文），模型可据此加宽 `old` 消歧。

## 2. 关键设计

### 2.1 workspace 沙箱（安全第一）
所有 fs 工具路径必须经**单一共享辅助** `resolveInWorkspace(root, p)`：归一化 → realpath → 包含校验，返回绝对路径或确定性 deny。**禁止每工具各写一份校验**（路径版 "no scattered branches"）。该辅助的三层防线（锐评修正，字面"前缀校验"可被绕）：

1. **归一化**：`path.resolve(root, p)` 折叠 `..`、相对/绝对输入。URL 编码（`%2e%2e`）非攻击面——工具输入是 JSON 字符串不经 URL 解码，字面量而已。
2. **realpath 防符号链接/junction**：`path.resolve` 纯词法，不解析 symlink——工作区内指向外部的 symlink/junction（node_modules 常见）可穿透前缀校验。必须对**最深已存在祖先**做 `fs.realpath` 后再校验（write 目标可能不存在：realpath 父目录 + 拼余段）；Windows 8.3 短名（`REPO~1`）同被兜住。TOCTOU 残余风险记录在案。
3. **包含校验（边界 + 大小写双保险）**：不能裸 `startsWith(root,...)`——`G:\repo` 是 `G:\repo-evil\a.txt` 的前缀。正确写法：
   ```
   const inside = p === root || p.startsWith(root + path.sep)   // POSIX
   // win32: 双方 toLowerCase() 后再比较（盘符 g: vs G:）
   ```
`\\?\` 设备路径 resolve 后不匹配前缀 → 被拒（安全侧），测试固化此行为。

与 AGENTS.md 的"工作区感知"一致：fs 工具的可见世界就是工作区。

### 2.2 Bash 的权限定位（锐评修正：沙箱之外，显式声明）
- **bash 不受 §2.1 fs 沙箱约束**——shell 里 `cd ..`/读任意可达路径均可。开启 bash = 授权该会话以进程用户权限读写执行任意可达路径。此边界必须显式文档化，不得让"fs 工具有沙箱"暗示"系统有文件边界"。
- `write` 同样是任意执行的半张门票（可落 `.ps1`/`.bat` 供后续执行）——"bash 唯一有副作用"的表述不成立；write 也属敏感工具。
- M3.5 **默认不注册** bash，由 `AppConfig` 显式开启（`bash: true`）。细粒度权限（allowlist/execpolicy 自举）留 M4。
- 实现约束：`cwd` 钉死在 workspace（相对路径默认落在工作区内，唯一免费软约束）；timeout 用 `setTimeout + kill` 兜底（不依赖 Bun.spawn 内建 timeout 的版本差异），Windows 杀进程树用 `taskkill /T /F`（`proc.kill()` 只杀直接子进程，`cmd /c` 的孙进程会成孤儿）；模型可报 `timeoutMs` 但服务端 clamp 到硬上限（60s）；**非零 exitCode 是数据不是错误**（模型靠它自纠），`isError` 只留给 spawn 失败/timeout；command 本身即语义，不做 sanitize（信任边界 = 用户开关，sanitize 只会造出假安全）。

### 2.3 注册与发现
- `packages/runtime/src/tools/` 下每工具一个文件，`createBuiltinTools(options)` 工厂统一产出（复用现有 `Tool` 契约；`ToolCtx` 需加 `signal?: AbortSignal` 传给工具，使 bash 等可响应中断——这是一处小 core 改动）。
- 与既有覆盖逻辑并存：显式 `tools` > `plugins` > `builtin`。**显式空数组视为"显式覆盖=无工具"**（用 `!== undefined` 判断，堵住 truthy 穿透）。
- butler 会话（asButler）同样获得 builtin fs 工具（push 语义），fs 工具属 user-scope 与但管权威无冲突。
- 输入 schema 用 JSON Schema 声明（`inputSchema`），模型可自省参数。

### 2.4 结果形状（模型友好）
- **read 带行号前缀**（`  12→content`）——没有行号，edit 消歧与"改第几行"推理都要模型自己数行；这是让模型自纠的最廉价杠杆。默认上限 1000 行（单行超 2000 字符截断），`limit` 可调。
- read/search/list 带截断标注（`"truncated": true` + `totalMatches?`）；search 默认 100 命中；**默认排除 `.git`/`node_modules`/二进制文件**（否则真实仓库 search 吐乱码或慢死）。
- 错误即数据：文件不存在/权限拒绝等以 `{ error: "..." }` 返回（工具内捕获），不抛成 provider 崩溃——与"model-visible ⟺ logged"一致；仅未预期异常走 loop 的字符串归档路径。非零 exitCode（bash）同样是数据。
- **workspace root 对模型可见**：工具 description 带根路径 + system context 注入一行"工作区根：`<path>`"——否则首轮模型只能猜相对路径。

### 2.5 DAG / 子会话接线（M3/M2b 交互缺口，锐评 I 项）
- **DAG 节点必须拿到工具**：`DagDeps.tools` 默认接 `createBuiltinTools({ workspace })`——否则 DAG 子节点依旧裸奔，§0 的"成本平衡（便宜模型跑子任务）"落空。
- **workspace 继承**：`dag-runner` 与 `hub.spawn` 都写 `location: ""`。当前单 app 现实下工具是工厂期闭包绑死父 workspace，恰好一致；但**子会话不经 `app.prompt`，AGENTS.md 发现与 system context 对子节点不生效**——子节点既没工具说明也没 workspace 上下文。**已知缺口**：标记为 M4 SessionManager 接管 workspace 继承（`Session.Created.location`）时解决；M3.5 只在 spec 记录现状，不虚拟实现。
- DAG `runSession` 未传 caller/toolCtx（`ctx.caller` 落默认 `{kind:"parent"}`）——builtin fs 工具不读 ctx，无碍；但 write/edit 日后若要审计（建议与 butler 同管道），此线需补（M4）。

## 3. 测试计划

- 每工具单测（临时目录夹具）：正常路径 + **symlink 越界用例（回归锁攻击面 A）** + **`G:\repo-evil` 前缀边界用例** + 越界拒绝 + 截断 + 错误形状。
- bash：默认未注册；开启后可执行；**timeout 杀进程树用例（Windows）**。
- edit：old==new / 空 old / 多处命中返回结构化信息 / CRLF 归一化写回。
- 集成：真实模型（MiniMax）跑一个"用 read+list 回答仓库里 package.json 的 name"任务——验证模型能自主调用工具并综合结果（已有冒烟框架可挂）。

## 5. 边界

- 不做：web fetch、read 图片/PDF（多模态 fast-follow）、记忆工具、细粒度权限（M4）、跨 workspace 工具。
